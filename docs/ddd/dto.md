# DTOでドメインオブジェクトを直接公開しない理由

## なぜDTOが必要か

DDDでは、ドメインオブジェクトの振る舞い（メソッド）をアプリケーションサービス（UseCase）以外から呼び出すことは避けるべきとされる。しかし、UseCaseの戻り値としてドメインオブジェクトをそのままクライアントに渡してしまうと、クライアント側からドメインオブジェクトのメソッドを直接呼び出せてしまい、意図しない依存が生まれてしまう。

これを防ぐために、ドメインオブジェクトを直接公開せず、代わりにDTO（Data Transfer Object）を経由してデータをやり取りする方針が使われる。

## DTOを使うことで防げること

- UseCaseを参照するclientがDTOだけを参照できるようにすると、ドメインオブジェクトのメソッドを呼び出すことができなくなる
- 結果として、クライアントからドメインオブジェクトへの不要な依存を防げる

## DTOのデメリット

DTOを導入すると、ドメインオブジェクトとは別にDTO用のクラスを都度用意する必要があるため、記述量が増えて面倒になる。

## 対策

DTOを自動生成できるツール・ライブラリを使うことで、この記述量増加の問題は緩和できる。
